# 三条命令，从「一堆素材」到「能交出去的片子」

这篇只讲一件事：**先看计划、再快渲一版看节奏、最后出交付版**。

为什么值得单独写一篇：这三步的顺序是反直觉的。多数人上手就直接渲交付档，
等二十分钟看到成片，才发现第三镜多停了半秒——改一个数字，又等二十分钟。
把中间的「预览」这一步插进来，改一次节奏的代价就从二十分钟变成十几秒。

前提：`python -m cutwright doctor` 全绿（ffmpeg / ffprobe 找得到）。

---

## 第 0 步：手边没有素材也能跑

```bash
python examples/demo/make_media.py --out examples/demo/materials
```

它会合成 7 段竖屏素材 + 一段配乐，够把后面的命令跑通。

---

## 第 1 步：先看计划（不渲、不建目录）

```bash
python -m cutwright build examples/demo/shotlist.json -o out/demo --dry-run
```

```text
计划: 4 段切片 → .../out/demo/xxx.mp4
  画布 540x960 @ 30.0fps，成片 6.0s
  [1] clip01.mp4       入点   0.200s +1.50s  → _build/seg_55302f6842.mp4
  [2] clip02.mp4       入点   0.500s +1.50s  → _build/seg_1da789d01d.mp4
  ...
  （切片名带内容摘要：名字一样就是能直接复用的缓存）
```

看三件事：

1. **每段切的是哪一秒**——`入点 0.200s +1.50s` 是「从素材 0.2 秒处取 1.5 秒」；
2. **总共几段**——段数就是 FFmpeg 要跑的次数，估时间先数这个；
3. **切片名**——带内容摘要，改一句字幕、动一个入点，只有那一段的名字会变。

这一步 0.5 秒左右，而且**不创建输出目录**：`--dry-run` 就是拿来看的。

---

## 第 2 步：快渲一版，只看节奏

```bash
python -m cutwright build examples/demo/shotlist.json -o out/demo --fast
```

- 跑的是「预览档」：切片 `veryfast` / 成片 `veryfast`，码率更低；
- 结尾一定会提醒一句「这是快速预览，要交付就同一条命令去掉 `--fast`」；
- 这一版**不是成片**，只用来确认：第三镜长不长、转场卡不卡在鼓点上。

样例素材上大约 5 秒出片（全量 demo 的对照见下一节）。

---

## 第 3 步：出交付版（就是去掉 `--fast`）

```bash
python -m cutwright build examples/demo/shotlist.json -o out/demo
```

同一张分镜表、同一个输出名，只是走交付档（切片 `medium` / 成片 `slow`、`crf 18`），
并且会顺手做成片体检（时长、画幅、响度、真峰值、黑场、静音）。

> ⚠️ 预览切片和交付切片**不共用缓存**（摘要里带 `preview` 旗）。所以「先 `--fast`
> 看一遍，再正式渲」会把切片重跑一次。这不是 bug：拿预览的码率去拼交付版，画质就
> 定死在预览上了。

---

## 什么时候真的快得起来

同一台机器（Windows，`ffmpeg 7.x`，1080×1920）实测：

| 场景 | 耗时 |
|---|---|
| 小样（540×960 / 4 镜 / 6 秒）· 计划 | 0.5 秒 |
| 小样 · `--fast` 预览 | 4.7 秒 |
| 小样 · 交付档 | 4.9 秒 |
| demo 全量（1080×1920 / 7 镜 / 13.8 秒，3 个镜头带推近）· 冷启 | 16.9 秒（`--fast`） / 18.7 秒（交付） |
| 同上，切片都在、只是重出成片 | 12.5 秒 |

这里有个值得知道的来龙去脉：**推近（Ken-Burns）以前是全流程最贵的一步**。
旧实现用 `zoompan`，它是单线程的，一镜 3 秒要 115 秒——demo 全量交付要 203 秒。
现在换成「2 倍画布 + 逐帧改缩放 + 居中裁剪」（`scale=…:eval=frame`），同一镜 3.8 秒，
整整 37 倍；两条滤镜链的画面 SSIM 0.985（肉眼看不出差别）。

所以现在：

- 冷启一条 7 镜竖屏片：**十几秒**，不是几分钟；
- `--fast` 相对交付档只省一点点（这台机器上 16.9 对 18.7）——它省的是编码，而编码已经不是瓶颈；
- 还想更快的话，`--opt jobs=4` 让多镜并行，或者把切片留着复用（改字幕、换配乐不必重切）。

老实现没删：`--opt zoom_engine=zoompan` 可以退回去（只在极老的 ffmpeg 上才有必要）。
